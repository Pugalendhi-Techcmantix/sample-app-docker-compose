# Role & User Master CRUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Roles + Users CRUD app (React/Vite → Express → PostgreSQL) that runs locally with `docker compose up`.

**Architecture:** This is a monorepo. `backend/` is an Express REST API that uses Prisma ORM 8 for data access and runs `prisma migrate deploy` on startup. `frontend/` is a React SPA that is built by Vite and served by nginx; nginx also proxies `/api` to the backend. `docker-compose.yml` wires `db`, `api` and `web` together.

**Tech Stack:** Node 24 LTS, Express 5, Prisma ORM 8 (`prisma` + `@prisma/client` + the PostgreSQL driver adapter the prisma-8 guide prescribes), zod, Vitest + Supertest, React 19, Vite, React Router, PostgreSQL 17, nginx, Docker Compose, Playwright (smoke + screenshots).

**Spec:** `docs/superpowers/specs/2026-11-25-role-user-crud-design.md`

## Global Constraints
- JavaScript ESM (`"type": "module"`) in both packages; no TypeScript.
- Prisma: pin an exact published **8.x** release; never `latest`. Before writing any Prisma code, run `npx prisma skills sync` and read the synced `prisma-8/SKILL.md`. Follow it for the generator output path, client construction and driver adapter. Where this plan and that guide disagree on Prisma API details, the guide wins.
- All DB access goes through the single Prisma client in `src/db.js`. There is no raw `pg` usage, except the `TRUNCATE` in test helpers, which goes through `$executeRawUnsafe`.
- Ports: web `8080`, api `4000`, db host `5433` → container `5432`.
- DB names: `crud` (app), `crud_test` (tests). Credentials come from `.env` only; `.env` is git-ignored and `.env.example` is committed.
- JSON fields are camelCase; DB columns are snake_case.
- Error body is always `{ error: { message, details? } }`. Never send a stack trace or a raw Prisma/DB error message to the client.
- Email and role-name uniqueness is case-insensitive. Trim all strings before validating.
- Use only the packages listed in Tech Stack. There is no CORS: the browser calls `/api` on the same origin, through the nginx proxy in Docker and the Vite proxy in dev.

## Review Focus
1. **Deleting a role that is still in use** → 409 `"Role is assigned to N user(s)"`, and the UI shows the message. Owner: Task 3 test, Task 7 UI.
2. **Duplicate email/name with different case** (`A@x.com` vs `a@x.com`) → 409, not 500. Owner: Tasks 3 and 4 tests.
3. **Non-numeric or unknown id** (`/api/users/abc`, `/api/users/99999`) → 404, not 500. Owner: Tasks 3 and 4 tests.
4. **Creating a user with a roleId that does not exist** → 400 with field `roleId`, not a 500 FK error. Owner: Task 4 test.
5. **API is down or the DB is not ready at startup** → compose starts `api` only after the db healthcheck passes, and restarts it if `migrate deploy` fails. The UI shows an error banner instead of a blank page. Owner: Tasks 2, 5 and 9.

### Task 3: Roles API

**Files:** Create `src/validation.js`, `src/routes/roles.js`, `test/roles.test.js`; Modify `src/app.js` (mount), `src/errors.js` (add `mapPrismaError`)

**Interfaces:**
- Consumes: `prisma`, `HttpError`, `createApp`, `resetDb` (Task 2).
- Produces:
  - `parseId(raw: string) => number`. It throws `HttpError(404,'Not found')` if the value is not a positive integer.
  - `roleSchema` (zod): `name` trimmed, 1–50 chars; `description` trimmed, ≤255 chars, optional, nullable.
  - `mapPrismaError(err, ctx: { unique?: string, fk?: {status, field?, message} }) => HttpError | null`, which maps:
    - `P2002` (or a raw `23505`) → 409 `ctx.unique`
    - `P2003` → `ctx.fk`
    - `P2025` → 404 `'Not found'`
  - Role JSON: `{ id, name, description, createdAt, updatedAt }`. Prisma's camelCase models are returned as-is.

- [ ] **Step 1: Write the failing tests** in `test/roles.test.js`. Call `resetDb()` in `beforeEach`.
  - `POST /api/roles {name:'Admin', description:'All access'}` → 201 with `id` and `name:'Admin'`
  - `POST` with `name:''` → 400, `details[0].field === 'name'`
  - `POST` with `name:'admin'` when `'Admin'` exists → 409 `"Role name already exists"`
  - `GET /api/roles` → 200 array sorted by name
  - `GET /api/roles/abc` → 404; `GET /api/roles/99999` → 404
  - `PUT /api/roles/:id {name:'Super Admin'}` → 200, and `updatedAt` > `createdAt`
  - `DELETE /api/roles/:id` (unused) → 204, then `GET` it → 404
  - `DELETE` a role used by 2 users (create them with `prisma.user.create`) → 409 `"Role is assigned to 2 user(s)"`
- [ ] **Step 2:** Run `npx vitest run test/roles.test.js`. Expected: FAIL.
- [ ] **Step 3:** Implement the router.
  - Map a zod error → 400 `"Validation failed"` with `details` (one entry per field).
  - Before create or update, run `prisma.role.findFirst({ where: { name: { equals, mode: 'insensitive' }, NOT: { id } } })`. If it finds a role, return 409. The `lower(name)` index is the backstop for races and is mapped by `mapPrismaError`.
  - `updatedAt` is handled by `@updatedAt`.
  - DELETE first runs `prisma.user.count({ where: { roleId } })`. If the count is above 0, return 409 with the count. `onDelete: Restrict` is the DB backstop.
- [ ] **Step 4:** Run the tests. Expected: all pass.
- [ ] **Step 5: Commit** with message `feat(api): roles CRUD`.
